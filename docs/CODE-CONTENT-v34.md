# 代码索引内容复用 v0.34

**简体中文** · [English](en/CODE-CONTENT-v34.md)

普通推送不再重新写入所有文件的文本与倒排关系。内容以仓库、缓存周期和 Git blob SHA 唯一定位：未修改、重命名或复制的文件复用同一内容记录，跳过该 blob 的 R2 读取和三字符分词；不同仓库之间不共享内容。新的路径映射仍遍历固定默认分支的完整 Git 树，构建完成后原子发布，搜索仍按当前账户与项目权限读取完整已发布快照。

## 数据与重建

迁移 `0027_shared_code_content.sql` 增加普通 D1 表 `code_contents`、`code_content_grams`，路径文档通过外键引用内容。旧 `code_documents` 文本和 `code_postings` 保持可读，后台分批转换到格式 2；迁移后即使旧 Worker 曾消费请求，新 Worker 也会通过版本字段继续补建。无需改变 R2 Git 对象、DO 仓库或 Git 协议。

手动重建创建新的持久缓存周期，从 Git 重新读取内容。构建开始时以请求计数和强制标志作条件更新，避免吞掉并发重建请求；构建中的新强制请求保留到下一轮。普通推送继承周期，可以复用已写入但尚未发布的同仓库内容。每步内容、路径和游标仍在同一 D1 batch 中提交；丢失响应后从持久游标恢复。

发布前旧快照继续可查，默认分支切换仍立即隐藏旧分支结果。每轮先清理最多 5 个过期路径文档，再清理最多 5 个无引用内容；外键级联清理对应倒排关系。删除仓库同样先删除路径、再删除内容、最后删除仓库。内容不会在仍被发布或构建中的文档引用时回收。

## 可见计数与边界

项目搜索页及 `GET /api/repos/:namespace/:repo/code-index` 的已发布 `coverage` 增加：

- `index_version: 2`：使用共享内容格式。
- `reused_files`：复用已有内容的文件数，包含同一批次内的复制文件。
- `created_contents`：本轮新建的不同内容记录数。
- `written_postings`：本轮新写入内容倒排关系数。

原 `bytes`、`postings` 仍按每个路径累计预算，因此复制文件可能增加逻辑计数，但不增加实际内容写入。被跳过的二进制、超大或无效文本不会建立负缓存。文件、路径、文本量、倒排量限制沿用 [v0.32](CODE-SEARCH-v32.md)。这不是 Git 树差异遍历，也不索引全部分支和历史；路径映射仍有读写成本，不能据此承诺固定延迟或 Cloudflare 账单降幅。

D1 仍使用可导出的普通表。备份恢复须同时保留既有身份/权限数据和 Cloudflare 服务配置；D1 导出不包含 R2/DO 的全部状态。回退至不理解共享内容的 v0.33 时，需要暂停代码搜索或重新生成旧格式索引，不能直接声称旧 Worker 能读取格式 2。Git 数据格式不受影响。

## 验证

`npm run check` 验证事务恢复、并发请求、混合格式查询和权限。`npm run test:code-content` 使用真实 Workers、原生 Git 与浏览器，检查重命名/复制复用、手动全量重建、默认分支切换和撤权，并清理独立夹具。远端需要 `ALLOW_REMOTE_ACCEPTANCE=1`、`TEST_ORIGIN`、私有 `ONESTORAGE_TOKEN_FILE` 和可用的 `PLAYWRIGHT_MODULE`。验收和清理期间不要重新部署被测环境。
