# 项目归档（v0.10）

**简体中文** · [English](en/ARCHIVE-v10.md)

项目所有者在设置页面选择「归档为只读」或「取消归档」。空间项目必须由该空间的当前 owner 操作；原始创建者不会绕过空间所有权。管理员身份本身不提供归档权限，仍可使用既有管理员仓库删除与空间所有权恢复流程。

`PUT /api/repos/{namespace}/{repo}/lifecycle` 接收 `{ "archived": true, "revision": 0 }`。版本来自项目详情的 `lifecycle_revision`；归档和恢复均递增版本，陈旧版本返回 409，不能覆盖另一个操作者。只读 PAT 和委托 Git JWT 不允许修改生命周期。

## 归档契约

- 项目 UUID、Git 引用、R2 对象、Issue/MR/评论、Wiki 历史、Release、CI 历史和产物均保留，正常授权读取、clone/fetch、搜索、源码归档和 fork 导出继续可用。
- 拒绝普通、临时、导入 Git 推送、LFS 上传、网页/API 写文件、分支/标签/notes、合并与审阅、Issue/评论/标签/里程碑/看板、Wiki/Release、上游配置与同步、流水线配置及新任务、部署版本与环境切换。
- 同一 D1 事务取消 queued/running CI，清除租约，并取消 pending 同步任务。归档期间不能领取 Runner 任务；恢复后旧租约仍失效，不会复活已取消运行。已经启动的隔离函数/外部进程可能继续至超时或 Runner 检测到取消，但不能提交产物或成功状态。
- 已公开的应用保留最后激活版本并继续访问。归档禁止激活或回滚；如需下线应用，先在归档前关闭环境公开访问，或恢复项目后再操作。
- 访问管理、Runner 凭据撤销、个人收藏/关注及通知阅读继续可用。归档不是凭据永久吊销；恢复后现有有效凭据按当前权限使用。
- 删除和垃圾回收仍可运行，恢复不会自动重试 CI 或同步任务。

## 写入一致性

生命周期变更通过每仓库 Durable Object 的串行队列，与 Git 引用发布排序。在队列内读取 D1 的持久归档状态，因此早先通过外层鉴权的排队 Git/LFS 请求也会被拦截；DO 重启后同样读取该屏障。D1 的归档标记、版本、任务取消、当前所有权复查和审计为一个事务。

协作表的数据库触发器在实际 INSERT/UPDATE/DELETE 时检查归档状态，关闭「鉴权后发生归档」的竞态。已发布但尚未投影到 D1 的合并结果在归档前完成补偿；存在未确认上游写入或 fork 初始化时，生命周期变更返回 409，要求先完成恢复。已完成操作的事件与 Webhook 仍允许投递，历史不会因归档丢失。

云端产物与环境发布在 D1 事务再次检查未归档仓库及运行租约。归档使上传中的结果失去发布资格；成功确认未发布时回收其 R2 对象。外部 Runner 必须继续遵守心跳/租约协议。

v0.11 已提供 [项目转移与重命名](TRANSFER-v11.md)，支持保留归档状态转移。归档没有解除现有 Git 对象图和内存预算限制。
