# 空间 CI 变量与密钥（v0.24）

空间所有者可在「空间管理 → CI 变量与密钥」管理共享定义，空间内项目按任务 `variables` 名称和 `environment` 显式选择。项目 CI 页面单独显示继承的名称、环境、分支限制、版本、来源空间和可用性；不显示值，也不允许项目维护者修改空间定义。管理员没有自动越过空间所有者权限。

## 选择与使用

按以下顺序选择每一个名字：项目精确环境、项目 `*`、空间精确环境、空间 `*`。空间定义不会覆盖已有项目定义。最高优先级定义暂停、失去所有者授权或不允许当前分支时直接失败；不会绕过限制去读取低优先级凭据。删除覆盖定义后，新任务才恢复下面一层的选择。

配置方式、Workers 输入、外部 Runner 环境变量、保护分支及 MR 限制与[项目变量](CI-VARIABLES-v20.md)一致。例如空间中保存 `CLOUDFLARE_API_TOKEN` 和 `CLOUDFLARE_ACCOUNT_ID`，项目任务显式选择这两个名字即可共享部署凭据。空间密钥的使用范围包括空间内所有符合条件的项目，应由所有者决定哪些构建代码可以接触它。

每个空间最多 100 个定义；项目的 100 个定义限额独立计算。每个任务仍最多选择 30 个名字、总值 64 KiB。支持精确环境和 `*`、明确分支名和 `*`。当前空间为单层，没有嵌套子组或实例级变量，也没有 GitLab 文件类型变量及完整 YAML 展开兼容。

## 安全与变更

共享值使用独立空间 AAD 加密，首次使用再写入任务自身的加密快照。项目和空间值不相互复制；新项目可使用既有定义。跨项目快照各自绑定任务和版本，已完成历史的脱敏快照不因定义删除而丢失。

只有当前空间所有者可管理共享变量，写入事务再次验证用户、角色及有效的写入会话/PAT。变量原所有者必须仍是空间所有者且账户启用；其仅保留项目维护者身份不足以继续授权空间凭据。接管会暂停变量并增加版本，须主动重新启用。

修改、轮换、暂停、接管、删除或撤销所有者资格，会取消各项目已绑定该定义的未完成运行和父工作流，使执行租约失效。项目转出空间后不再读取原空间值，旧快照也不能用其他仍在原空间的项目替它授权；新运行使用目的空间规则。归档、删除和受保护分支变化继续使用既有取消机制。

首次绑定时原子核验当前优先级、定义版本、空间归属、角色、保护和租约，避免选择期间新增的高优先级覆盖被绕过。绑定成功后继续使用已固定的版本；后来创建另一项覆盖定义不改写这个快照，新任务按新顺序选择。已经交给执行中代码的值无法收回；日志脱敏减少意外泄露，不阻止可信代码把值变换后输出或写入产物。

## API、部署与验收

- `GET/POST /api/workspaces/:slug/ci/variables`：所有者列出元数据或创建定义。
- `PUT/DELETE .../:variable`：携带当前 `revision`；更新省略 `value` 保留旧值。
- `POST .../:variable/take-ownership`：携带版本，接管并暂停。
- 项目 `GET .../ci/variables` 保持 `variables` 为项目定义，新增 `inherited` 空间元数据数组。

迁移 `0019_workspace_ci_variables.sql` 增加独立表和投影视图，扩展撤销触发器；不改写项目变量密文或现有任务快照。部署前导出 D1，在独立副本验证迁移、外键、完整性和既有数据数量，保留 `CREDENTIAL_ENCRYPTION_KEY`。仅需发布主 Worker，Git/R2/DO 格式、编译 Worker、应用网关均不改变。

`npm run check` 包含继承与撤权的真实 SQLite 测试。`npm run test:workspace-variables` 在真实 Worker 和发货版外部 Runner 验证共享、覆盖、暂停拒绝、兄弟项目、MR/重试、租约撤销、日志与历史脱敏；`npm run test:workspace-variable-ui` 在 localhost Chromium 验证空间入口、CRUD、所有者权限、项目继承展示及手机布局。生产执行 API 验收仍须显式 opt-in，临时项目及空间在结束时删除。

参考 [GitLab CI/CD 变量文档](https://docs.gitlab.com/ci/variables/) 的分组所有者管理和项目优先模式；本实现的暂停、撤销及快照契约以上述说明为准。
