# v0.17 完整 Git pack 缓存

v0.16 的首次导入已经可以接收 35 MiB / 2,108 个对象，但冷 clone 仍要逐个读取松散 R2 对象并压缩。v0.17 在正式对象之外增加可丢弃的 R2 完整 pack 缓存，降低重复 clone 的读取次数。正式松散对象、引用发布格式及各个 Fork/后台读取路径保持兼容；不需要数据库迁移或容器。

## 权限与内容

每次请求仍先经过当前账户/仓库权限、项目版本和 DO 删除屏障，然后验证 wants 对当前可见 refs 的可达性，计算准确的对象集合。只有没有已知 have 的完整传输使用缓存；增量协商仍使用正式对象路径。缓存键包含仓库 UUID、排序后的完整对象 ID 集合以及输出格式版本，不能凭缓存定位符下载对象。

缓存保存非 delta PACK v2 字节，Git v0/v2 的确认和 sideband 帧在缓存之外生成。include-tag、命名空间、分支选择改变对象集合时不能误用原缓存。入站 pack 可能含未引用对象或外部 delta 基础，因此从不直接作为出站缓存。更改压缩实现或输出格式时必须更新 `pack-v2-full-zlib-v1` 版本键，保持中途重建的字节确定性。

## 分块、回退与回收

- pack 分为最多 128 个 4 MiB 分块，沿用 512 MiB 出站上限。流式生成时只保留一个缓存写入块；已有对象缓存和预取预算另计，并非整个 isolate 只使用 4 MiB。
- 分块写入使用 R2 条件写入和 SHA-256；读取时核对长度和 SHA-256，校验前不发送该块。R2 条件写入及校验参数依据 [官方 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。
- 完成所有分块后，才在 DO 中原子发布描述与保留标记。每个仓库只有一个缓存槽；替换之前先回收旧缓存。清理失败时继续正常 Git 传输，但不增加新缓存数据。
- 缓存保留 24 小时；写入前持久化清理标记并安排 alarm。未完成、取消或失败的构建由串行 alarm 回收。仓库删除时，现有 R2 前缀清理同时删除缓存及其 DO 元数据。
- 缺块、错误长度、SHA-256 不匹配或缓存读取错误都会使描述失效，并从正式对象重新生成。如果之前已发送部分已验证数据，重建会跳过相同的字节前缀，继续同一次 Git 响应。正式对象读取错误仍向客户端报错。
- 取消响应必须等待已开始的 R2 操作与生成器退出，之后才释放仓库队列。缓存清理错误不能阻塞事件投递和同步恢复。

## 验收

`npm run test:pack-cache` 在隔离私有空间建立 1,100 个小文件和两个 5 MiB 随机文件，共 1,105 个 Git 对象；执行协议 v2 冷 clone、v0 与 v2 重复 clone、增量 push/fetch、变化后的冷/热 clone、严格 fsck、取消下载及匿名拒绝，最后清理仓库和空间。

单元测试覆盖实例重建、缺失/损坏分块与中途回退、仓库/对象集合隔离、TTL、写入/发布/回收失败、取消及在途 I/O 排空、不可达 wants 和增量协商。195 项单元测试与类型检查通过。本地专项通过 45 项 Git/HTTP 检查，1,105 个对象 / 10 MiB 数据首次无 pack 缓存 clone 约 902 毫秒，重复 clone 约 148–153 毫秒；变化后的首次/重复 clone 约 893/143 毫秒。日志中的正式 R2 对象读取由首次 959 次、变化后 1,104 次，降为缓存命中时 0 次，命中另读取 3 个 pack 分块。本地核心回归另通过 43 次 API 断言及 Git/LFS 等检查。模拟器耗时不代表生产性能；生产候选 `c71307ca-b92c-4c1d-9f26-06de6d0177e4` 的专项通过 43 项 Git/HTTP 检查；另有普通写入和版本化 CI 回归 49 次断言通过。

## 后续

此缓存改善重复 clone；首次导入、首次 cold clone、不同对象集合交替请求和同仓库串行排队仍需继续优化。下一阶段处理读租约与全实例内存预算，再推进永久 packed 对象布局。完整 CI/CD、身份集成和协作平台目标仍见 [ROADMAP](ROADMAP.md)，本版本不代表完整 GitLab/Gogs 已完成。

## 生产测量（2026-09-08）

测试为同一个隔离私有仓库、1,105 个对象、10 MiB 随机文件数据，首次入站 pack 为 10,544,939 字节。这里的“首次”表示没有匹配的完整 pack 缓存，部分小对象仍可能在内存缓存中；并非重启整个 Cloudflare 节点的测量。

| 操作                    |             耗时 | 正式对象 R2 读取 | pack 缓存操作  |
| ----------------------- | ---------------: | ---------------: | -------------- |
| 首次 push               |        94.364 秒 |                1 | 不使用出站缓存 |
| 首次 v2 clone           |        56.049 秒 |              959 | 写入 3 块      |
| 重复 v0 clone           |         9.768 秒 |                0 | 读取 3 块      |
| 重复 v2 clone           |         4.957 秒 |                0 | 读取 3 块      |
| 增量 push               |         5.131 秒 |                — | 不使用出站缓存 |
| 增量 v2/v0 fetch        | 5.436 / 3.330 秒 |             各 0 | 不使用出站缓存 |
| 提交变化后首次 v2 clone |        41.774 秒 |            1,106 | 重建 3 块      |
| 提交变化后重复 v2 clone |         7.226 秒 |                0 | 读取 3 块      |

每个 clone/fetch 都执行原生 Git 严格 fsck 和引用一致性检查。缓存命中时观察到的正式对象缓存及预取字节均为零，另有至多 4 MiB 的当前 pack 分块；不将这些组件指标当作整个 V8 堆峰值。测试还包含匿名拒绝及主动取消下载后的队列释放。尾日志中两条 canceled 对应测试 Git 下载的外层/内部请求，无异常记录；后续 ls-remote 在 30 秒内完成。

这是单次实际网络测量，不能推导所有地区的吞吐或 SLA。尤其首次导入和无匹配缓存的 clone 仍较慢。权限绕过、损坏回退与故障注入由上述单元/协议测试覆盖，未在生产正式仓库注入损坏。

两组生产验收均已完成清理：测试仓库、空间和本地 Git 夹具已删除；用户原有 PAT 保留。专项仓库的 R2 前缀已确认为空。

另观察到一条清理阶段的 alarm canceled（13 毫秒、CPU 0、无异常）；测试清理最终成功且 R2 前缀为空，未将此事件计为 HTTP 验收失败。
