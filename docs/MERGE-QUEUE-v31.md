# 合并队列

**简体中文** · [English](en/MERGE-QUEUE-v31.md)

OneStorage v0.31 增加由 Cloudflare Durable Objects 驱动的合并队列。Git 对象保存在 R2，排队状态、审阅和 CI 状态保存在 D1；候选流水线沿用 Cloudflare Queues、Workers 执行器或已配置的外部 Runner，不需要容器。

## 使用

1. 在目标项目的 CI 页面保存流水线。可以使用保存的 JSON 配置，或指定目标分支中的 JSON 配置文件。自动推送触发开关不影响显式入队。
2. 创建合并请求，在请求页面选择合并方式并点击“加入合并队列”。需要维护者或所有者权限；支持快进、三方合并和压缩提交，压缩不能与仅快进同时选择。
3. 在请求页面或项目合并请求列表查看候选提交、候选流水线和阻塞原因。队列区域每 10 秒更新，不刷新正在编辑的审阅表单。
4. 按需在受保护分支设置“必须通过合并队列”。开启后禁止普通直接合并及绕过队列的目标分支写入。

同一目标分支按入队编号先进先出，其他目标分支轮流处理。审阅未通过、冲突、无效配置或候选 CI 失败都会阻塞队首，后面的请求不会越过它。维护者可以取消；修复问题后重新入队。流水线页面的普通重试产生独立运行，不替换队列绑定的候选运行。

## 提交与 CI 的一致性

队列记录源 SHA、目标 SHA、合并请求修订号和合并选项。DO 在发布任何引用前生成真实合并候选，将对象写入 R2，然后启动绑定该候选 SHA 的 CI。成功后发布的就是同一个候选 SHA，不重新生成提交。

- 配置文件来自固定的**目标 SHA**，源分支修改的配置文件不会作为当前候选的流水线配置执行。保存的内联配置也参与指纹计算。
- CI 必须是队列指定的根运行且成功，其他源提交流水线不能代替它。工作流沿用根运行对子任务的状态聚合。
- 候选运行的来源为 `merge_request`，沿用现有不受信任合并请求的变量、密钥和私有包限制，不自动获得受保护的发布凭据。
- 候选未发布时可通过已有的授权按 SHA 读取或 Runner 源码归档读取；原生 Git 分支列表不提前增加候选引用。
- 目标分支前移会更新请求的目标快照和修订号，取消旧候选 CI，并重新生成候选。旧批准绑定旧目标，因此需要的批准必须重新提交。
- 源分支变化或请求被编辑、刷新、关闭会取消原入队意向，需要重新审阅并入队。队列不会自动纳入后续源提交。

发布前再次检查队首位置、当前账户与项目权限、生命周期、最新审阅、源和目标快照、配置指纹及候选 CI。Git 引用、合并结果、Issue 关闭计划和事件标记在 DO 中一起持久化；D1 合并状态投影可以幂等恢复，响应丢失不等于合并未发生。应先读取队列及分支状态再重试。

## 权限与恢复

入队需要有效的写入会话或 PAT。入队后的意向最长保留 24 小时；正常退出登录或撤销该单独凭据不自动撤销已经接受的意向，可以在队列中显式取消。账户安全 epoch 改变、账户禁用、项目归档/转移/删除会取消意向和活动候选 CI。维护权限被收回会在下一次驱动时取消，并在发布检查中再次拒绝。

Fork 来源仍需当前可读。来源 DO 提供仅内部绑定可调用的已发布引用读取，避免两个项目互相等待写锁。源、目标两个 DO 没有分布式原子锁：检查读取的是已提交快照，最终最多合并固定的、已审阅的源快照，不纳入未审阅的新提交。

DO 先持久化唤醒标记再写入队意向；每个候选代次使用固定 CI 事件编号，D1 响应丢失后恢复同一个运行。SQL 约束会拒绝已经失效意向的新 CI，也会取消尚未来得及关联到队列行的旧运行。

## API 与限制

| 操作     | 接口                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------- |
| 查看队列 | `GET /api/repos/:namespace/:repo/merge-queue`，可选 `mr_id`                                     |
| 入队     | `POST /api/repos/:namespace/:repo/merges/:id/queue`，`revision` 必填，可选 `strategy`、`squash` |
| 取消     | `DELETE /api/repos/:namespace/:repo/merge-queue/:entry`                                         |
| 要求队列 | `PUT /api/repos/:namespace/:repo/protections`，`require_queue: true`                            |

每项目最多 100 个活动条目，每请求最多一个活动条目；接口另返回最近 20 个完成条目。驱动通常以 15 秒间隔分阶段执行，正在处理的 Git 流及其他恢复任务可推迟运行；不保证固定完成时间。仍受现有 Git 图、对象、CI 并发和执行时限限制。

本版采用逐个候选验证，不做投机并行合并列车或多请求合并批次。不是完整 GitLab API/YAML 兼容实现。总平台目标继续进行，验证证据见 [VERIFICATION-v31.md](VERIFICATION-v31.md)。
