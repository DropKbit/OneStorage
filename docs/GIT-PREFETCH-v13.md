# v0.13：有界 Git 对象预取

**简体中文** · [English](en/GIT-PREFETCH-v13.md)

v0.12 真实 5,424 对象、42 MiB 随机内容的生产冷克隆需要 6–11 分钟。v0.13 在保持持久闭包索引与流式 pack 的基础上，将出站对象读取改为有界并行；单次大仓库首次导入和 pack 缓存仍在后续目标中。

## 读取与内存契约

只有当前 refs 授权检查及闭包规划选中的对象才可预取。每个仓库的已验证索引提供大小，最多同时保留四个读取结果/在途读取，预留载荷总量最多 8 MiB；正在交给压缩器的对象仍占用名额与字节预算。没有已验证大小时按每个对象 8 MiB 保守预留，因此回退为串行读取。

异步读取可以乱序完成，但 pack 按原计划顺序输出。消费者未继续读取时，只会完成已排队的窗口，不会继续扫描整个仓库。R2 内容仍通过 ObjectStore 的长度、SHA-1 和对象类型校验；预取再验证返回的 OID 和大小与计划一致。压缩器仍逐对象、按 16 KiB 输入块工作。

预留字节并非 isolate 内存峰值：哈希输入、R2 canonical 数据、共享与请求缓存、压缩状态和可达集合也占用内存。新增日志 `prefetchPeakBytes`、`prefetchPeakObjects` 只表示窗口预留峰值。

## 取消及故障

每个在途读取立即安装成功/失败处理器。任一失败停止补充窗口，并在抛出错误前排空已开始的读取。取消响应或空闲超时关闭迭代器时同样等待在途读取结束；外层仓库队列的释放时机不变。因此转移、归档、删除与后续请求不会越过仍可能更新缓存的旧下载。

本次不改变引用事务、可见性判定、不可变对象写入、入站 pack 限额或仓库生命周期策略。

## 验证

- 145 个单元测试与 TypeScript 检查通过，新增覆盖四路并发、乱序完成、有消费者背压时不继续排队、混合对象的 8 MiB 预留、缺失索引回退、错误元数据、读失败排空、pack 校验和及响应取消后的队列完成顺序。
- 本地 5,424 对象/42 MiB 原生 Git 验收 49 项通过，含 v0/v2 clone、增量 push/fetch、fsck、匿名拒绝和中断下载。两个全量传输的窗口峰值均为 7,340,499 字节、4 个对象；本机克隆约 3.2/3.1 秒，不能用作云端性能结论。
- 本地核心 Git/LFS/并发/权限回归 43 项 API 断言及原生 Git 操作通过。生产同规格原生 Git 验收 47 项通过，见下方测量。
- 跨 Fork 审阅浏览器专项补验 60 项通过（另有 201 次分页夹具请求），包含创建/切换来源、讨论/回复分页、独立审批、讨论门禁、快照 CI 和实际合并；通用浏览器回归另 43 项通过。覆盖见 [v0.7 补验记录](VERIFICATION-v07.md)。
- 首次 v0.13 生产验收在第一批推送报告持久化/引用更新失败，临时仓库与空间已清理；发生在下载预取前。随后启用完整实时请求日志重跑，六批推送、两种协议 clone/fsck、增量 push/fetch、取消下载及后续访问均通过，未捕获相同错误。历史遥测查询返回鉴权失败；首次错误原因仍未定位，不能宣称已修复。

## Cloudflare 生产测量

相同规模与操作顺序：6 批推送生成 5,424 个对象、42 MiB 随机内容，然后执行 v2、v0 全量克隆。以下是各版本一次成功验收的数据，网络与云端缓存状态不是严格控制变量，不能作为 SLA。

| 操作          |      v0.12 |      v0.13 |
| ------------- | ---------: | ---------: |
| v2 全量 clone | 640,543 ms | 180,763 ms |
| v0 全量 clone | 366,723 ms |  94,475 ms |
| 增量 push     |   4,192 ms |   4,146 ms |
| v2 增量 fetch |   5,519 ms |   5,211 ms |
| v0 增量 fetch |   3,496 ms |   4,175 ms |

两个全量克隆的耗时分别减少约 72% 和 74%。读取次数仍为 5,423/5,424，读取字节为 44,365,169/44,365,416；预取窗口峰值均为 7,340,499 字节、4 个对象，请求对象缓存峰值为 7,546,743/7,546,745 字节。两个增量 fetch 均命中共享对象缓存，R2 读取为零，窗口峰值为 514 字节、3 个对象。指标不包含整个 isolate 内存，未将缓存预算作为进程 RSS 宣称。

取消下载的日志显示读取 101 个对象后排空，随后原生 Git ls-remote 在 30 秒门槛内完成；临时仓库、工作空间和本地 Git 数据已完全清理。

本轮只改善读取调度，六批推送仍各耗时约 76–94 秒；取消大下载后可再次访问 refs，但正常全量传输仍持有同仓库队列。入站限额、冷克隆 R2 操作数与同仓库等待仍需继续改进。

下一步仍包括合并对象存储/pack 缓存、流式入站导入与同仓库读并发；完整目标见 [大仓库计划](GIT-SCALE-PLAN.md) 和 [持续能力矩阵](CLOUD-NATIVE-v05.md)。
