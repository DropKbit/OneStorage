# v0.29 Git 持久审计验收

**简体中文** · [English](en/VERIFICATION-v29.md)

本阶段完成原生 Git 引用与审计意图的原子持久化、D1 去重投递、多引用存储事务及网关确认诊断。它不代表完整 GitLab/Gogs 目标完成；行为与限制见 [Git 提交与审计](GIT-RECEIPTS-v29.md)。

## 故障证据

v0.28 源码推送退出 1、HTTP 500，但远端 main、随后 fetch 和独立镜像严格 fsck 均确认 `ab1a2053f43c30ff972090216e57cc5d99aeedb9` 已完整提交，对应同步审计缺失。历史日志接口返回 403；后续三次隔离生产推送均成功，过滤实时日志未复现原异常。

测试单独注入「DO 已成功提交，随后 D1 审计失败」，在修复前稳定得到 500，修复后返回原有 Git 成功响应。这个证据证明旧代码存在该缺陷，**不能据此认定历史那次 500 一定由 D1 审计引起**。

## 单元、迁移和存储验证

`npm run check` 的类型检查与 312 项测试通过，新增 7 项验证覆盖：提交后故障隔离及可信 actor、原子引用/审计记录、D1 中断恢复、不确定提交、DO 删除标记失败、通知去重、积压上限、失败事务、无变更、历史身份、20 条投递批次、超过 128 键的分批原子事务，以及网关未知结果的 incident 诊断与隐私。

`npm run build:production` 通过。生产 D1 先导出至本机私有文件，在独立 SQLite 数据库中恢复并应用迁移，确认 67 张现有表的行数不变、399 条既有 audit 记录保留、完整性检查通过且无外键违规。此处验证的是 D1 备份，不是完整 R2/DO 灾难恢复演练。随后本地和生产都应用了 `0023_git_receipts.sql`。

## 真实原生 Git

本地最终验收 29 次 API 响应检查（包含审计轮询，不含清理），生产 14 次。两处都执行了：

- 三次实际原生 push，核对远端 SHA 和异步审计。
- 一个原子请求创建分支与标签，另一个请求删除它们；各只有一个 `refs_updated=2` 的审计。
- 一个原子请求创建 129 个分支，再整体删除；各只有一个 `refs_updated=129` 的审计。这在实际 Cloudflare 上验证了超过 128 个存储键时的事务处理。
- 无变更 push 和受保护分支拒绝均没有伪造成功审计；被拒绝的提交没有前移远端引用。
- 独立镜像 clone 与 `fsck --strict` 通过，主分支匹配最后一次接受的提交。

生产 fixture 最后接受的提交为 `185d08a5e060df570320f35a4a188ace2aa6ca9f`，7 个成功事务分别产生唯一事件 ID。该 fixture 的 Git 请求捕获到 39 个经过筛选的日志事件，没有 HTTP 5xx 或运行异常；这不代表未采集流量的全局可用性保证。
