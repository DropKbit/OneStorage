# Git 写入恢复与诊断（v0.15）

v0.12–v0.14 的生产验收曾出现偶发写入失败。现存记录不能定位根因；本轮增加阶段诊断和有界 R2 暂态恢复，不把历史异常直接归因于 R2，也不声明历史问题已经修复。

## 不变的数据约束

不可变 Git 对象仍通过 R2 条件写入保存，验证可达对象后才发布 DO 引用。重试只包围单次 R2 `get` 或条件 `put`，不会重新执行整个 Git 请求、D1 事务或引用发布。若响应丢失时引用已经改变，客户端须先查询引用，再决定是否重试。

R2 返回明确的服务错误码 10001、10043、10054 或 10058 时，每次操作最多额外尝试两次，同一个 ObjectStore 请求总计最多四次额外尝试。延迟从 150ms 开始指数增长并添加抖动；10058 的首次等待至少 1.1 秒。未知、权限、配置、校验和引用冲突直接失败，不扩大重试范围。

条件写入若首次已经成功但响应异常，下一次仍带 `etagDoesNotMatch: "*"`。返回对象已存在时，读取并比较完整规范化内容；内容冲突仍拒绝，不能用重试覆盖已有对象。两个 I/O 通道中的在途操作全部结束后才返回失败，引用不会在对象尚未保存时前移。

以上错误码与条件写入语义依据 Cloudflare 的 [R2 错误码](https://developers.cloudflare.com/r2/api/error-codes/) 和 [Workers R2 API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。DO/D1 操作没有新增自动重试，见 [DO 错误处理](https://developers.cloudflare.com/durable-objects/best-practices/error-handling/)。

## 诊断与排查

未预期的 Git 后端错误生成独立 incident ID。HTTP 提交接口返回 `incident_id` 和 `X-OneStorage-Incident`；原生 Git 的 report-status 拒绝信息包含同一个日志关联 ID。日志标识 metadata、object-read、object-write、object-verify、object-index 或 ref-publish 阶段，以及可识别的 R2 代码、D1 标记、平台 retryable/overloaded 标记和编译位置。

诊断不会输出原始异常消息、SQL、请求头、凭据、源码、仓库文件路径或完整堆栈。即使暂态重试随后成功，仍记录仓库 ID、阶段、错误码及重试次数；次数也加入已有 Git 传输指标。阶段名称只说明在哪一层观察到异常；没有对应提供方错误码或其他证据时，不能据此认定具体根因。

## 验收

故障注入覆盖成功写入后的响应失败、冲突内容、持续暂态故障、请求总预算、双路操作排空、并发读取去重、不确定引用发布不重放、诊断隐私及原生 Git 错误协议。

本轮还修正一项已复现的错误分类：thin pack 读取外部基对象失败时，旧解析器会吞掉所有异常并报告“无法解析或循环依赖”。现在先允许包内后置基对象完成解析；仍需要外部对象时，保留真正的存储异常并在 Git 拒绝信息中返回 incident ID。确定缺失的对象和畸形 delta 继续按无效 pack 处理。这一问题与历史 503 是否相关尚无证据。

`npm run test:git-reliability` 复用隔离的 Git/CI 验收夹具，再执行八次提交 API 写入、两个客户端争抢同一预期引用、陈旧引用重试和两次原生增量 push，最后 clone、校验分支并运行严格 fsck。它验证真实服务正常与冲突路径；提供方故障通过上述注入测试覆盖，不在生产环境人为破坏存储。

类型检查及 161 项单元测试通过。thin pack 的新增回归用例在修复前失败，修复后通过；真实本地核心集成再次通过 43 次 API 断言及原生 Git v0/v2、thin push、并发、二进制、LFS 和持久化检查。

写入专项本地通过 43 次、生产通过 53 次 HTTP/协议断言（计数包含轮询），均完成上述连续提交、引用竞争、增量 push、clone/fsck。生产完整工作流另通过 23 项语义检查、150 次 HTTP 断言，包括 JS 执行、依赖产物、外部 Runner、取消/发布门禁及 MR 配置来源。后者运行于本轮第一次候选部署；thin pack 修复随后通过本地回归，并随第二次候选部署接受生产写入专项验证。

生产测试没有观察到新的 503 或 R2 暂态重试。这是本次样本的结果，不能证明历史异常已消失或提供可用性 SLA。入站 pack 规模限制、同仓库串行访问和大导入仍是后续工作；完整 GitLab/Gogs 目标继续有效。
