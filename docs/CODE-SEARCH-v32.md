# 全局代码搜索 v0.32

本文记录初始实现；v0.34 已加入[同仓库内容复用](CODE-CONTENT-v34.md)，以下全量内容重写说明仅适用于 v0.32–v0.33。

全局搜索选择“代码”，输入至少 3 个 Unicode 字符。支持字面量子串、空间、路径子串、扩展名和归档筛选；ASCII 不区分大小写，其他 Unicode 精确匹配。每个命中文件返回首个匹配附近的片段与行号，点击打开索引提交的文件，分支继续前进不会使链接指向不同内容。默认“全部协作内容”仍包括项目、Issue、MR 和 Wiki，不自动混入代码。

项目“搜索”页显示索引状态、时间、覆盖数与跳过原因；维护者/所有者可以重建。归档项目可读取和重建派生索引。搜索及索引状态需要当前读取权限，管理员没有私有代码的隐式访问权；重建需要当前维护权限及会话/写入 PAT。撤销成员、会话/PAT 到期、禁用账户后重新搜索都会校验当前授权。部署令牌与 Git 委托 JWT 不支持这些接口。

## 数据与恢复

代码、Git 对象和原生 pack/HTTP 协议仍由 Workers JavaScript/WASM、R2 和 DO 提供。每个仓库 DO 在写入队列内分批遍历固定默认分支 Git 树，每步最多检查 256 个树条目、8 个文件。持久游标、文档和三字符倒排关系保存在主 D1；每步由同一 D1 事务更新，丢失响应后按已提交游标恢复。构建中新代号不可搜索，全部检查完成后原子切换已发布代号。上一代在普通推送后仍作为完整旧快照可用，结果标记 stale；默认分支元数据切换立即隐藏旧分支结果。旧代号和已删除项目的文档每次最多清理 5 个，关联倒排行通过外键及索引回收。

推送与上游同步成功事件写入持久索引意向，DO alarm 分批执行。默认分支切换把 DO 权威值和 D1 投影重试标记一起保存，alarm 在索引前恢复失败投影。每 5 分钟的现有 cron 为历史项目补建状态（每轮最多 50 个），唤醒最多 20 个待办项目；尝试时间在 RPC 前更新，避免无法唤醒的项目持续占用队首。临时索引失败保留游标与意向并重试，状态页显示通用错误；没有任意承诺的完成时限。频繁推送可能连续重建，现阶段不做未变 blob 的跨代增量复用。

主 D1 使用 `code_index_state`、`code_documents`、`code_postings` 普通表（迁移 `0026_code_index.sql`）。虽然 [D1 支持 FTS5](https://developers.cloudflare.com/d1/sql-api/sql-statements/)，其虚拟表有[导出限制](https://developers.cloudflare.com/d1/best-practices/import-export-data/)，本实现选择普通三字符倒排表，保留 SQL 导出路径。先按索引定位候选，再验证完整字面量；同一 D1 batch 校验实时身份、项目权限并读取结果与覆盖概况。搜索没有逐项目 Git RPC，也没有固定项目数量截断，但常见三字符会产生很多候选，不能据此宣称大型实例固定延迟。

## 覆盖边界与成本

只索引默认分支已发布快照的普通 UTF-8 文本文件；不索引全部分支、历史、评论、Git LFS 实际内容、子模块或符号链接，不支持正则索引和 Unicode 全语言大小写归一。原有项目 Git 搜索继续可用。

- 每文件最多 256 KiB、65,536 个不同三字符；NUL 二进制、无效 UTF-8、超大/复杂文件会跳过。
- 每项目最多检查 10,000 个文件、索引 64 MiB 文本或 2,000,000 条倒排关系。
- 路径遵循浏览器文件接口约束，最多 1,000 字节、64 层；无法访问的路径或目录记录跳过，未遍历子树标记 `unscanned`。
- 遇到项目预算停止后，覆盖数只描述已检查部分，状态为 `partial`，不会将未扫描文件算成已完整覆盖。
- 全局覆盖统计按可见项目汇总，路径/扩展名筛选不缩小项目覆盖统计。项目页面的构建计数与 `coverage`（已发布快照）在重建中可能不同。

倒排表是有成本的派生数据，文本和新旧代号共存会占用 D1 空间、读写行额度；上限是应用预算，不保证实例不会触及套餐/数据库容量限制。应监控 D1 容量和失败状态。D1 备份包含索引；也可从已保留的 Git/R2 数据重建，但 D1 导出本身不构成 R2/DO 的完整灾备。

## API 与验证

`GET /api/search?type=code&q=...&namespace=...&path=...&extension=ts`，支持 `archived=include|exclude|only`、`limit=1..50`（默认 30）、上下文绑定 `cursor`。关键词最多 128 个 UTF-16 单元，至少 3 个 Unicode 码点。返回 `results`、`has_more`、`next_cursor`、`coverage`；结果含路径、片段、行、blob SHA、索引提交/分支/时间及 stale。分页读取当前状态，不是数据导出快照。

`GET /api/repos/:namespace/:repo/code-index` 读取状态；`POST .../code-index/rebuild` 返回 202。已排队但未开始的新重建请求可合并；构建中的新请求会留到后续。待办先持久化，因此唤醒请求异常可由 cron 恢复。

开发验证：`npm run check`；本地 Workers 启动且迁移后，设置 `PLAYWRIGHT_MODULE` 运行 `npm run test:code-index`。远端需要显式 `ALLOW_REMOTE_ACCEPTANCE=1`、`TEST_ORIGIN` 与私有 `ONESTORAGE_TOKEN_FILE`；脚本创建并清理独立夹具，使用禁用 credential helper 的原生 Git 和浏览器，禁止在验收及清理期间重新部署该环境。
